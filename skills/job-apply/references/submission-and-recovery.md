# Approval, Receipts And Recovery

## Separate Gates

Preparing a form, accepting a specific privacy agreement, authorizing profile transfer, approving an exact CV and authorizing final submission are separate actions. Apply current host requirements at each gate. Show the exact current material in external signed-in Chrome before final submission approval. A user's request to build this skill does not submit the live application that inspired it.

Password creation/change, MFA and credentials belong to the user under applicable host rules; never save secrets in the ledger. Read terms/data recipients and ask when acceptance requires confirmation. No new paid platform, subscription, marketing/talent-pool enrollment or access expansion by default. Do not attest that the candidate personally completed a form when that is not true; hand off a personal-completion declaration. Stop at CAPTCHA/security/account restrictions without bypassing them.

Candidate AI-use rules matter. Preparation of a CV may be allowed while work samples, psychometrics, interviews or assessments prohibit assistance. Inspect the actual rule and separate stages; do not route around a restriction using another agent.

## Submit Once

After exact-copy approval, verify current page/requisition/attachment/answers still match, then Submit once. Read the resulting page. Validation errors are not success; repair the actual error, recheck relevant fields and seek new approval if substantive material changed. An ambiguous timeout is not permission to resubmit: check portal history, receipts and scoped email first. Preserve Unknown until evidence resolves it. Do not diagnose every Oracle error as a blank field; stop repeated unchanged server/rate-limit failures and checkpoint a bounded retry.

Success evidence may be a receipt ID, explicit confirmation page or actual employer acknowledgement. A job-board click-through, absent error, saved form, upload badge or timer is not sufficient. Preserve the receipt, exact documents and applied time. If the user submits personally, verify that outcome without sending again.

## Tracker And Continuity

Use the existing log and native spreadsheet, never a new parallel tracker. Inventory headers and valid status options before writing; update the same role row/track and read it back. `Prepared`, `Applied`, `Already applied`, waiting/blocked and validation-only are different states. If finite dropdown options lack a precise state, use a valid existing option and explain details in Next Action instead of inventing invalid status text. Record sheet row and evidence pointer. Do not mark Applied because preparation is complete.

Preserve changed local artifacts and verify current private Drive backup via configured mappings. Never change sharing to ease a review. Keep backup pending if it fails. Close confirmed-complete application/used-source tabs after receipts are saved, retaining unfinished forms, the tracker and requested review tabs. Never close unrelated user tabs.

On pause/interruption, save completed pages, unresolved fields and pending approvals, exact source revision and next action. Check current owner and user edits on resume. Never recreate a password/account, repeat a question already answered, or start a duplicate form solely because the previous model turn ended.
