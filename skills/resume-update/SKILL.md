# Resume Update

Maintain an editable resume and a verified matching PDF, not merely a plausible-looking export. This is an on-demand workflow, not an autonomous agent or scheduler.

## Resolve The Request

Choose the smallest applicable mode:

- **Content/tailoring:** change supported positioning or experience for the requested role, retaining the agreed design. Read [content-and-evidence.md](references/content-and-evidence.md).
- **Formatting:** repair layout and typography without rewriting career claims. Compare text before and after; unexplained differences stop finalization.
- **Export-only:** use the latest saved user-edited native file without content or layout changes. Export, verify and back up only.

Locate the selected variant, current task checkpoint, approved visual reference and latest user edits. Read [profile.md](references/profile.md) when a private profile is available. Do not mistake an older Desktop copy, application attachment or historical backup for the current master. A newly supplied user-edited Drive source must be reconciled before using an older local copy.

Check the actual document identity, timestamps, hashes and current app state. Preserve originals and submitted copies. Reuse the active working filename for ordinary repairs; create a tailored derivative only for a distinct requested purpose. Do not generate serial V2-V6 variants to compensate for failed edits.

## Native Editing

For an existing Pages resume, make all substantive and layout changes in Pages, then export from that saved source. Read [native-pages.md](references/native-pages.md) before Pages changes or save recovery. For a Word-only variant, retain its native Word source and use the available document workflow; do not convert it to Pages without a reason.

Preserve the selected template's photo, icons, blue skill chevrons, section rules, font hierarchy, margins and bullet style unless the user asks to redesign. Template-specific measurements are not universal resume rules. Do not flatten text into pictures, patch a final PDF while leaving the source broken, or edit opaque Pages IWA data.

For photo distortion, section-banner alignment or Word/template reconstruction, read [layout-fidelity.md](references/layout-fidelity.md) before editing. Inspect the actual image and object geometry; copying a header or finding every heading in extracted text does not establish layout fidelity. When another agent/user owns the live source, inspect a timestamped snapshot and report against its hash rather than overwriting ongoing work.

Verify every page, not just the reported defect: title clipping and overflow; visible font runs including single letters; section alignment; bullet/paragraph indents and spacing; job boundaries; page breaks; duplicated objects; orphan headings; contact details and hyperlinks. Preserve user-adjusted spacing rather than globally replacing blank paragraphs. Fix the underlying native object or style, not its screenshot.

## Persistence, Export And Verification

1. Save, check the file on disk and reopen the exact native path. Confirm content and layout persisted. A click, an absent error, a thumbnail or an upload icon is insufficient.
2. Export from the verified saved native source. Prefer the app's PDF export. Record a Print-to-PDF fallback explicitly; an unsaved recovery print is not a final master.
3. Run the scoped read-only PDF checks with the applicable profile in [verification.md](references/verification.md). Inspect extracted text separately, then render and visually inspect **all pages** beside the approved reference. Investigate suspect mappings against native text and a second parser; a clean font audit is not clean text. Resolve findings or report them; machine checks cannot certify visual correctness or ATS compatibility.
4. Update the identified private backup mapping without expanding sharing. Verify the current revision and state whether proof is metadata/size or a downloaded hash match.
5. Open the exact final PDF in external signed-in macOS Chrome and verify the displayed document. Do not substitute an embedded browser. If external verification fails, retain the artifact and report the concrete blocked handoff. The editable source remains in its native editor; a Drive preview is not proof of editability.

Do not repeatedly retry a failing save/export. After one ordinary retry and one safe recovery attempt, preserve recoverable work and stop to inspect the failure. Never force-quit an app with unprotected user edits.

## Scope And Close-Out

Use existing personal-workflow/external-browser guidance where installed; otherwise apply the equivalent gates above. Ask only a consequential missing question after checking available evidence, not a new career interview on every invocation. Do not re-ask settled facts.

Keep internal commentary and workflow instructions out of CVs. Never send, apply, sign, publish or alter account access merely because this skill was invoked. For any later submission, follow the current exact-copy review and specific approval requirements; check prior receipts to avoid duplicates.

Record the selected source, changes, saved source/PDF paths and hashes, visual verification, backup evidence and remaining issues in the existing task checkpoint. Summarize briefly. Distinguish prepared, locally verified, backed up, handed off and submitted. Installing this skill does not fix other CVs, activate another client, or schedule future work.
