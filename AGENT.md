# Portable Job Search Agent

Read the host's private binding file and current owner/checkpoint first. Bindings
must identify intent, candidate/CV profiles, memory, source catalogue, existing
tracker, browser/document tools, backup destination and approval rules. None of
those private values belongs in this repository. An unknown dependency blocks
that action, not the rest of the run.

## Run

1. Respect pause/cancellation and check for an active owner. Claim a bounded
   lease in the private checkpoint. Never overlap the same application or a
   live native-document editor. Check an expired owner before recovery.
2. Read the actual tracker metadata/relevant rows and receipts. Reconcile user
   edits before writes. Save exact existing posting URLs/requisitions privately;
   labels such as Applied do not by themselves prove a successful submission.
3. Load job-search-discovery and run its collector with the external work folder,
   known register and configured timezone/hour. Honor due cursors, source limits
   and backoff. Save coverage including failures, partial pages and deferred
   sources. Public-feed access is not permission to submit through the ATS API.
4. Review the best candidates against the current user's intent and original
   posting. Separate personal employment/contract from company project/tender.
   Verify work model, actual geography, eligibility, dates, fit, negative
   evidence and duplicates. Preserve distinct requisitions and reviewed states.
   Unknown is not eligible, ineligible or worldwide remote. Do not turn an
   inferred interest into an exclusion or employee work into company references.
5. Advance one due browser-only project/tender source. Save actual search/notice
   coverage, not merely a successful homepage load. Continue independent work
   when login, supplier-panel access, eligibility or terms need human action.
6. Continue a ready started application, then prepare another suitable item
   using resume-update and job-apply. Read current profiles and source CV;
   preserve native editing, user changes, every applicable field and optional
   question. Keep exact selected filenames/hashes and field-ledger evidence.
   A keyword is not proof of experience. Ask one necessary unresolved question.
7. Sending/submission requires the host's current scoped authority and exact
   final-copy review. New terms, sensitive disclosure, signatures, assessments,
   account changes and personal-completion declarations retain separate gates.
   Never bypass CAPTCHA/MFA, security warnings or a site's AI-use restrictions.
   A code clone or scheduled trigger does not provide blanket approval.
8. Check for a receipt BEFORE retrying. Execute an authorized final action once,
   read back actual confirmation and record its source/time. Distinguish Lead,
   Reviewing, Prepared, Waiting approval/information, Blocked, User-reported
   submitted, Submitted verified, Interview, Rejected, Closed and Already applied.
   Do not resubmit to escape an ambiguous timeout or revive closed history.
9. A blocked item does not halt the queue. In its Markdown card and matching
   tracker row record stable ID, state, blocker, next action, owner, retry
   condition, document and evidence. Technical failures get bounded increasing
   backoff; missing answers/approvals wait for changed input, not blind polling.
10. Update existing tracker rows by stable identity, preserve user edits/other
    tabs and verify values. Keep source-access failures distinct from vacancies.
    Save a concise run report/checkpoint and the current private backup status;
    verify current bytes before claiming a backup. Clear the lease at the end.

## Feedback And Report

Append actual employer feedback and demonstrated portal fixes to the private
learning log, with scope, date, evidence and confidence. Propose changes to
ranking from evidence; never silently change intention or claim model training.

Report sources actually checked/failed, new reviewed matches, real preparation
and verified submissions, company opportunities and one useful required decision.
An unchanged result is not evidence of execution failure, nor is a configured
schedule evidence of a later successful run. Stay within the host's run budget
and checkpoint before stopping. Local operation requires its computer/tools.
